# Skill Selection for IChO Website

## Core Frontend & UI Design Skills (3)
1. **ui-ux-pro-max** - Builds professional company websites at Figma/x.ai level with:
   - Plain copy in a voice of its own
   - One section per screen
   - Equal edges
   - Real photographs and product UI
   - Hero entrance and two dealt moments on every page
   - Shader effects and scenes on tech pages
   - Quiet micro-interactions
   - Checker and finish gate that enforces it in a real browser

2. **design-taste-frontend** - tasteskill 2.5.1, the anti-slop frontend skill with:
   - Professional company websites at the level of figma.com and x.ai
   - Plain copy in a voice of its own
   - One system, one section per screen
   - Equal edges
   - Real photographs and real product UI (licensed stand-in photographs when client has none; a product render only when brief asks for 3D)
   - Hero entrance and one or two dealt moments on every page
   - Shader effects and scenes only on tech, gaming and software pages
   - Quiet micro-interactions
   - Checker and finish gate that enforces it in a real browser

3. **emil-design-eng** - Emil Kowalski's philosophy on UI polish, component design, animation decisions, and the invisible details that make software feel great.

## Motion & Animation Skills (3)
4. **animation-performance** - Keep web animations inside frame budget — animate composite-only properties, move off main thread when busy, find cause when animation drops frames
5. **animation-vocabulary** - Reverse-lookup glossary that turns vague description of web animation into its exact term
6. **choreograph** - Coordinate several elements that animate together — decide what moves, in what order, how much they overlap, and what stays still

## Design System Skills (2)
7. **design-system** - Token architecture, component specifications, and slide generation
8. **extract-design-system** - Extract design primitives from a public website and generate starter token files

## Quality Review Skills (2)
9. **break-ui** - Try to break a piece of UI by feeding it worst-case data — renders behind "Demo data / Worst case" toggle and reports everything that breaks
10. **review-animations** - User-only review-animations skill (I must invoke manually at checkpoints)

- **vercel-cli-with-tokens**: Not needed (GitHub Pages is simpler)
- **write-swift**: Not needed (not a Swift project)
- **vercel-react-native-skills**: Not needed (not a React Native project)
- **animate-expo**: Not needed (not Expo/React Native)
- **mobile-native**: Not needed (not native mobile)
